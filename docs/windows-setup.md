# Установка для Windows

## Быстрый запуск

1. Скачайте [Setup.exe из последнего релиза](https://github.com/GL1NoMe5/travel-tracker/releases/latest/download/Setup.exe).
2. Откройте файл. При желании измените папку в поле «Папка установки» или выберите её кнопкой «Обзор», затем нажмите «Установить». Оставьте включённым запуск после установки, чтобы сразу открыть карту.
3. В дальнейшем запускайте «Карта путешествий» через ярлык на рабочем столе или в меню «Пуск».

По умолчанию приложение устанавливается для текущего пользователя в `%LOCALAPPDATA%\Programs\TravelTracker`. Можно выбрать другую новую или пустую локальную папку, доступную для записи. Корень диска, сетевые пути и папки с перенаправлениями не поддерживаются; чужие файлы в выбранной папке не заменяются. Установщик не запрашивает права администратора, Node.js и npm не нужны. Используются встроенные компоненты .NET Framework и браузер по умолчанию. Для карты нужен браузер с WebGL2; для подложки и поиска — интернет.

Установщик не подписан цифровым сертификатом. Windows может показать неизвестного издателя или предупреждение SmartScreen. Подписанный выпуск пока не предоставляется. Официальные файлы проекта находятся в [GitHub Releases](https://github.com/GL1NoMe5/travel-tracker/releases).

## Как работает приложение

Ярлык запускает небольшой локальный сервер и открывает `http://127.0.0.1:5173` в браузере по умолчанию. Сервер слушает только этот компьютер; облачный сайт не создаётся. Файлы интерфейса, шрифт и границы стран входят в установщик. Подложка карты загружается из OpenFreeMap, поиск обращается к Nominatim.

После закрытия вкладки сервер остаётся доступен. Используйте значок приложения в области уведомлений Windows, чтобы снова открыть карту или выбрать «Выйти» и остановить сервер.

Если порт 5173 занят другой программой, приложение сообщает об этом. Оно не завершает чужие процессы и не переключается на случайный порт. Если ранее был запущен `npm run dev`, остановите его в соответствующем терминале перед запуском установленного приложения.

## Сохранённые поездки и обновление

Страны, места, даты и заметки автоматически сохраняются в `localStorage` браузера для адреса `http://127.0.0.1:5173`. Данные принадлежат профилю браузера, а не установочной папке. Если вы уже использовали приложение по этому адресу в том же профиле, коллекция останется доступной.

Другой браузер, другой профиль, приватное окно или адрес `http://localhost:5173` создают отдельное хранилище. Аккаунта, облачной синхронизации и пользовательского JSON-экспорта нет. Очистка данных сайта удаляет коллекцию; переустановка приложения её не восстанавливает.

Для обновления завершите приложение через его значок в области уведомлений, затем запустите новый `Setup.exe`. Установщик использует ранее выбранную папку и заменяет файлы приложения, сохраняя данные браузера. Чтобы установить приложение в другую папку, сначала удалите прежнюю установку через параметры Windows, затем запустите установщик снова. Данные браузера при этом сохраняются.

## Удаление

Откройте список установленных приложений в параметрах Windows, выберите «Карта путешествий» и удалите приложение. Деинсталлятор удаляет файлы приложения и ярлыки. Данные поездок в браузере сохраняются; их можно удалить отдельно через настройки данных сайта для `http://127.0.0.1:5173`.

## Сборка установщика из исходников

На Windows установите Node.js 22.12 или новее. Для сборки используются PowerShell и C#-компилятор установленного .NET Framework. Команды выполняются из корня проекта:

```powershell
npm ci
npm run build:setup
```

Команда собирает production-версию веб-приложения, локальный загрузчик и установщик. Результат:

- `release/Setup.exe` — готовый установщик с файлами приложения внутри.
- `release/Setup.exe.sha256` — контрольная сумма SHA-256.

Бинарные сборки, зависимости и кэш не добавляются в исходный репозиторий. `Setup.exe` публикуется отдельным файлом в GitHub Releases. Исходники Windows-оболочки находятся в `packaging/windows/`; данные стран и лицензии сторонних материалов сохраняются в проекте.

Сборка автоматически добавляет полные лицензии установленных зависимостей в `licenses/dependencies.txt` внутри пакета. Генератор работает локально по `package-lock.json`; для отсутствующих в npm-пакетах текстов используются закреплённые копии upstream-лицензий из `docs/third-party/`.

Контрольную сумму скачанного файла можно сравнить с `Setup.exe.sha256` из того же релиза:

```powershell
Get-FileHash .\Setup.exe -Algorithm SHA256
```

### Проверка пакета без установки

Извлеките содержимое в новую пустую папку:

```powershell
.\release\Setup.exe --extract .\release\extracted
```

Этот режим не создаёт ярлыки и запись в списке установленных приложений. Он предназначен для проверки упакованных файлов и запуска из извлечённой папки.

Для установки без окна и без автоматического запуска доступен режим:

```powershell
.\release\Setup.exe --silent
```

Он выполняет обычную установку для текущего пользователя, включая ярлыки. При обновлении используется зарегистрированная папка прежней установки. Для первой установки в другую папку передайте полный локальный путь:

```powershell
.\release\Setup.exe --silent --directory "D:\Applications\Travel Tracker"
```

Выбранная папка должна быть новой или пустой. Эти режимы не заменяют проверку запуска карты в браузере и сохранения поездок.

Автоматическая проверка распаковки и соответствия production-файлам:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File packaging/windows/Installer.Tests.ps1 -SetupPath release/Setup.exe
```

Параметр `-InstallLifecycle` дополнительно выполняет настоящую временную установку в стандартную папку, проверяет ярлыки, запуск, обновление и удаление. Вместо него можно передать `-CustomInstallLifecycle`: тот же сценарий использует уникальную папку внутри `.cache` с кириллицей и пробелами и проверяет отказы для неподходящих путей, несовпадающей регистрации и попытки переноса существующей установки. Эти два режима запускаются отдельно. Оба отказываются работать, если стандартная папка приложения, ярлыки или запись установки уже существуют. Данные браузера не читаются и не изменяются.

Для проверки обновления с доверенного предыдущего установщика добавьте `-PreviousSetupPath <полный-путь-к-старому-Setup.exe>` вместе с `-InstallLifecycle`. Первая установка использует старый файл, обновление — `-SetupPath`. Этот сценарий сравнивает веб-файлы обеих установок с текущим `dist`, поэтому предназначен для проверки изменений оболочки при одинаковой веб-сборке.

Проверки локального сервера выполняются через `packaging/windows/Launcher.Tests.ps1 -ExecutablePath <путь-к-TravelTracker.exe>` при свободном порте 5173.
